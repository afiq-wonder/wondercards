# Recommended Reading Order

Every contributor should follow this order.

## Step 1 — Understand WonderOS

Read these documents in sequence:

1. 00-StartHere

2. 01-Vision

3. 02-Identity

4. 03-WonderDNA

5. 04-Constitution

6. 05-Repository-Constitution

These documents explain:

- why WonderCards exists

- who we build for

- how we make decisions

- how the repository is organised

---

## Step 2 — Understand the Architecture

Continue with:

```

docs/architecture/

```

This explains:

- system architecture

- application layers

- module relationships

- runtime flow

---

## Step 3 — Read ADRs

```

docs/adr/

```

Architecture Decision Records explain *why* important technical decisions were made.

Always check existing ADRs before introducing a new architectural pattern.

---

## Step 4 — Read Standards

```

docs/standards/
```

Coding conventions, naming, documentation rules, testing expectations, and repository standards.

## Step 6 — Read Blueprints

```
docs/blueprints/
```

# Documentation Principles

Our documentation follows a simple philosophy.

**Vision before code.**

**Architecture before implementation.**

**Documentation before assumptions.**

**Tests before release.**

---

# AI Contributor Checklist

Before generating code, every AI contributor should understand:

- Vision

- Identity

- WonderDNA

- Constitution

- Repository Constitution

- Architecture

- Standards

If any of these are unclear, documentation should be updated before implementation continues.

---

# Repository Philosophy

WonderCards is built for the long term.

Every document should make the project easier to understand, easier to maintain, and easier to grow.

Documentation is treated as part of the product—not as an afterthought.
